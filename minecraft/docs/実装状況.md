# 実装状況（v0.2.0 第2弾まで）

## 検証の方法

この開発環境には Minecraft の実行環境（PC・Switch・Realms）がないため、**実機での動作は第1弾・第2弾とも一切確認していません。**
代わりに次の検証を行いました（詳細は [テスト結果](テスト結果.md)）。

- **型チェック**：Mojang 公式の型定義 `@minecraft/server@2.0.0`・`@minecraft/server-ui@2.0.0` で全スクリプトを検査（存在しないAPI・誤った引数がないこと）
- **静的検証**：JSON構文、manifest の UUID（第1弾から変更されていないこと）・相互依存、import 先の実在、アイコン・言語キーの対応
- **模擬エンジンでのテスト**：`@minecraft/server` の動作を真似た模擬実装の上で `main.js` を起動して操作を再現。**第1弾のコードで実際に作ったセーブデータ**からの更新も検証。模擬実装は実機を完全には再現しません

## 実装済み機能（第2弾）

詳しい仕様と数式は [第2弾 仕様書](第2弾_仕様.md)、才能の一覧と確率は [才能一覧](才能一覧.md)。

### レベル・経験値
- 独自のレベルと経験値（バニラの経験値とは別）。必要経験値は `40×L^1.5 + 60×L`
- 経験値付与の共通処理（モンスター・ボス・ダンジョン・クエスト・特殊イベント・試練）。後続のシステムは1行で経験値を付与できる
- 余剰経験値の繰り越し・複数レベル同時上昇・報酬キーによる二重付与防止（一度きりの報酬にも対応）
- 追いつき補正（パーティ内で遅れている人ほど経験値が増える。最大2倍）
- 不在プレイヤーには付与しない
- 【暫定】バニラのモンスター討伐で経験値（36種。管理者が無効化可）

### 存在階級・限界突破の基盤
- 一般級(50)・超人級(100)・英雄級(150)・伝説級(200)・神話級(300)・半神級(500)・神級(999)・未知の領域
- レベル上限の管理、限界突破回数・履歴の保存
- 突破条件の判定の仕組み（条件は未定義のため通常は突破不可。管理者テストでのみ突破）
- 上限到達後の余剰経験値：保留（上限あり、突破時に加算）／捨てる をワールド設定で選択

### 能力値・派生能力値
- 8能力値（筋力・耐久・魔力・精神・敏捷・器用・幸運・知力）。初期値は設定ファイルで変更可能
- 基礎・成長・振り分け・才能・職業・装備・一時効果を別々に管理し、毎回ゼロから再計算（重複加算なし）
- 派生能力値17種＋属性耐性8種を計算・保存・参照可能（他システム・不在時の参照用に計算結果も保存）
- 割合補正・成長率補正・能力値・派生能力値に上限

### HP・MP・スタミナ
- HP：バニラの体力と連動（二重ダメージなし・最大値超過なし・死亡処理はバニラのまま）、自然回復
- MP：自然回復、スキル用の消費共通処理（不足時は使用不可・何も消費しない）
- スタミナ：ダッシュで消費・休息（停止/しゃがみ/睡眠）で早く回復・0で疲労、疲労時の制限をワールド設定で選択
- レベルアップ時・リスポーン時に全回復

### 自由能力振り分け
- 1レベルにつき5ポイント。1/5/10ずつ・内容確認・確定前の取り消し・未使用ポイントの保存
- 確定済みは戻せない。再振り分けの仕組み（権利を消費）は将来の特殊アイテム・試練用に用意

### 才能・潜在能力
- 先天性才能40種（F〜EX）。初回参加時のみ抽選、シード固定で引き直し不可
- 才能ごとに：固有ID・名前・説明・等級・抽選確率・能力値補正・派生補正・属性耐性・成長率補正・職業適性・スキル習得への影響・覚醒条件・進化先
- 後天性才能14種（剣・槍・弓・斧・拳の心得、打たれ強さ、狩人の勘、夜を歩く者、巨獣狩り、逆境の目覚め、旅人の脚、および魔法・回復・守護系＝後続機能が条件を加算）
- 才能進化：複数分岐・優先度つき。実動作例として剣術系2系統（各3段階）＋弓・槍
- 隠された潜在能力10種。覚醒まで非公開、覚醒時は専用演出。条件は行動・実績・レベル・才能・特殊イベント（フラグ）の組み合わせ
- 成長率：才能によって能力ごとの自動成長が変わる（振り分けとは独立）

### メニュー・HUD
- ステータス：概要（レベル・経験値と必要経験値・存在階級・職業・HP/MP/スタミナ・基礎能力値・未使用ポイント）、能力値の内訳、派生能力値、能力ポイント振り分け
- 才能：所持才能（等級・由来）、才能の詳細（効果・進化の軌跡）、覚醒済み潜在能力
- HUD（アクションバー）：HP・MP・スタミナ・レベル・経験値・職業。変化時と2秒ごとのみ更新。個人設定で非表示可
- Switch のコントローラーで操作できるボタン形式（しゃがみ＋使用の操作は不使用）

### 管理者向けテスト機能
- 経験値付与・レベル設定・能力ポイント付与・HP/MP/スタミナ変更・才能付与・才能進化テスト・潜在能力覚醒テスト・限界突破テスト・ステータス再計算・セーブデータ確認（メニューとコマンドの両方）
- 管理者タグ所持者のみ。一般プレイヤーにはメニューに表示されず、コマンドも拒否

## 実装済み機能（第1弾）

### アドオンの基本構造
- ビヘイビアーパック・リソースパック・manifest（BP⇔RP 相互依存）
- 安定版 Script API のみ使用（`@minecraft/server 2.0.0`、`@minecraft/server-ui 2.0.0`）。実験的機能は不要
- 機能別のファイル分割（第2弾時点で86ファイル）。ゲーム内容は `content/` のレジストリに追加する方式（ID重複を拒否）

### プレイヤーデータ管理（4-2）
次の項目をプレイヤーごとに独立して保存する構造を用意しました（具体的な成長処理は未実装）。
プレイヤー識別ID／レベル／経験値／職業／職業レベル（職業別）／HP・MP・スタミナ（現在値・最大値）／基礎能力値（筋力・体力・敏捷・器用・知力・精神・幸運）／未使用能力ポイント／先天的才能／後天的才能／隠された潜在能力（抽選用シード付き）／スキル／熟練度／装備（9スロット）／金貨／称号／冒険者ランク／クエスト進行／NPC好感度／個人倉庫／ダンジョン攻略実績／限界突破状況／種族／個人設定／参加記録

### ワールド共有データ（4-3）
メインストーリー進行／地域解放状況／ダンジョン攻略状況／ボス討伐状況／世界唯一の装備の所有状況／世界唯一の称号の獲得状況／特殊イベント／ダンジョンの途中再開情報／データ構造のバージョン（＋アドオンのバージョン履歴・復旧記録）／ワールド設定（行動制限・人数別調整・NPC補完の切り替え）

### 初回参加処理（4-4）
- 初回：種族 人間・レベル1・無職・能力 一般人相当（全能力5、HP100/MP10/スタミナ100）・金貨0、その他初期状態
- 冒険者の書を配布（捨てられない・死亡時に失わない）
- 再参加：初期化せず保存データを読み込む（参加処理は何度呼ばれても二重実行しない）

### セーブシステム（4-5）
- **自動保存**：10秒ごとに「変更があったデータ」だけを最大2件ずつ保存（負荷分散）
- **重要な更新時の保存**：参加・退出・設定変更・行動制限変更は即時保存
- **終了時の保存**：ワールド終了直前イベントで全保存（実機で書き込み可能かは未検証。自動保存で補う）
- **再ログイン時の読み込み**・**ワールド再起動後のデータ維持**
- **データ破損の検知**：長さ＋チェックサム＋JSON構文で検証
- **二重保存**：A/B 2つの保存枠を交互に使用。保存の確定は最後の1書き込みで行うため、保存中の中断でも前回データが残る
- **復旧処理**：最新の枠が壊れていれば前回の枠から復旧。管理情報が壊れていても保存枠から新しい方を復旧。両方壊れていれば破損データを退避してから初期化し、本人と管理者に通知
- **データ構造のバージョン管理・移行**：データごとにバージョンを記録し、読み込み時に順番に移行。欠けた項目は自動補完、未知の項目は削除しない
- **新しいバージョンのデータの保護**：アドオンを古い版に戻した場合などは読み取り専用にして上書きしない
- **識別IDの復旧**：プレイヤー側の識別IDが失われても、索引から同じデータに戻す
- 保存は ASCII 化して分割するため、日本語や絵文字があっても保存上限の計算が正確で、分割による文字化けが起きない

### マルチプレイ基盤（4-6）
- プレイヤーごとにデータを完全分離（アドオン独自の識別IDで管理し、名前は識別に使わない）
- 同じ識別IDを持つ別人が同時参加した場合は新しいIDを発行してデータ共有を防ぐ
- ストーリー等はワールドで共有
- 不在プレイヤーのデータは変更されない（オフラインのプレイヤーへの更新は拒否）
- 途中参加・途中退出に対応
- 人数別難易度の倍率表（1～4人）と NPC 補完の差し込み口（適用処理は未実装）
- 5人以上の参加時は警告表示

### RPG専用メニュー（4-7）
- 冒険者の書を「使う」と開く（空中・ブロックどちらに向けても可）。しゃがみ操作は不使用
- ステータス／職業／スキル／才能／装備／称号／クエスト／冒険者情報／ダンジョン情報／倉庫／設定
- 各ページで保存データの現在値を表示し、未実装の機能は「今後実装予定」と表示
- 設定：保存通知の ON/OFF、今すぐ保存、データ状態の確認、［管理者］行動制限の設定、［管理者］最近のエラー
- チャット欄が開いていて表示できない場合は自動で再試行、連打による多重表示を防止

### 完全RPG型の基盤（4-8）
- ブロック破壊（採掘）・ブロック設置（建築）・ブロックの使用（作業台・かまど・チェスト等）を個別に禁止できる仕組み
- 既定ではすべて OFF。管理者が設定画面またはコマンドで切り替え
- クリエイティブモードと管理者タグの所持者は対象外

### 処理負荷対策（4-9）
- 毎tick処理なし（自動保存の確認は10秒に1回のみ）
- データはメモリ上に保持し、保存領域への読み書きは参加・退出・保存時だけ
- 自動保存は1回あたりの件数を制限して分散
- 退出したプレイヤーのデータはメモリから解放
- 全イベント処理をエラー隔離し、1つの失敗がほかに波及しない。エラーは管理者に通知し、設定画面で確認可能

## 既知の問題・制約

1. **実機で未検証**です。上表のとおり、すべての判定項目は模擬環境での確認にとどまります。
2. **冒険者の書の「使用」イベント**：特別な使用動作（食べる・投げる等）を持たない独自アイテムで `itemUse` が発火することを前提にしています。実機で開かない場合の代替として、ブロックに向けての使用（別イベントで処理）と `/scriptevent noguchi:menu` を用意しています。
3. **終了時の保存**：ワールド終了直前イベント内で保存領域に書き込めるかは未確認です。書き込めない場合でも、重要な更新は即時保存、それ以外は最大約10秒分の変更が失われる可能性があるにとどまります。
4. **設置の禁止は簡易判定**です。手に持ったアイテムと同じIDのブロックが存在する場合のみ禁止します。レッドストーンの粉・種・バケツなど「アイテムIDと設置されるブロックIDが異なるもの」は止められません。
5. **クラフトの禁止**：安定版 API にクラフト自体を止める仕組みがないため、作業台などのブロック使用を禁止する方式です。インベントリ内の2×2クラフトは止められません。
6. **5人以上の参加**は拒否せず警告のみです（プレイヤーの強制退出は行わない方針）。
7. **HP・MP・スタミナ**は RPG 内部の値で、バニラのハート（体力）とはまだ連動していません。
8. **日時表示**は UTC です（実行環境のタイムゾーンを取得できないため）。
9. **識別IDの復旧**は、Minecraft がプレイヤーに割り当てるエンティティIDがワールド内で変わらないことを前提にしています。通常はプレイヤー本人に保存した識別IDが使われるため、この経路はほとんど使われません。
10. **管理者タグの付与**にはチートの有効化が必要です（チートを有効にすると実績が解除されなくなります）。
11. **ビヘイビアーパックの UUID を変えるとセーブデータが読めなくなります**（動的プロパティはパックごとに保存されるため）。今後のアップデートでも絶対に変更しないでください。
12. 対応バージョンは **1.21.90 以降**です。それより古い Switch 本体のバージョンでは読み込まれません。

### 第2弾で追加された既知の問題・制約

13. **HP の自然回復は小さい**：HP はバニラの体力を基準にしているため、RPG の HP 自然回復（5秒で1程度）はバニラの体力に換算するとごくわずかです。バニラの満腹度による回復はそのまま働きます。
14. **最大HPを上げてもバニラのハートの数は変わりません**。RPG の HP は「ハートの割合 × 最大HP」で表示されるため、最大HPが上がると同じダメージで減る割合は変わらず、表示上の数値だけが大きくなります。防御力などによる実際の被ダメージの軽減は戦闘システム（後続）で実装します。
15. **スタミナ切れでもダッシュ自体は止められません**（安定版 API にダッシュを禁止する機能がないため）。代わりに鈍化（移動低下）を付与します。
16. **移動速度・積載重量・攻撃力・防御力などは計算のみ**で、ゲームの動きにはまだ反映していません。
17. **HUD はアクションバーを使う**ため、ほかのアドオンやコマンドがアクションバーを使うと表示が重なることがあります。HUD は2行表示で、画面の小さい携帯モードでは文字が詰まって見える場合があります。
18. **バニラのモンスターで経験値を得る仕組みは暫定**です。独自モンスター実装時に置き換えるか、管理者設定で無効化してください。
19. **効果音・パーティクル名はバニラのもの**（`random.levelup`・`random.totem`・`minecraft:totem_particle` など）を使っています。実機で鳴らない・出ない場合も処理は止まりません。
20. **後天性才能の行動記録**：命中の判定は `entityHitEntity`、射撃は `projectileHitEntity` を使います。トライデントの投擲・クロスボウの判定は手に持っているアイテムで行うため、持ち替えた直後は別の武器として数えられることがあります。
21. **第1弾から更新したプレイヤー**は、更新後の最初の参加時に初期才能が抽選されます（第1弾では才能が未実装だったため）。
22. 才能の「職業適性」「スキル習得への影響」は保存・表示のみで、効果はまだありません。
