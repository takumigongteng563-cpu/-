# 実装状況（v0.1.0 第1弾）

## 完成判定の検証結果

この開発環境には Minecraft の実行環境（PC・Switch・Realms）がないため、**実機での動作は一切確認していません。**
代わりに次の3種類の検証を行いました。

- **型チェック**：Mojang 公式の型定義 `@minecraft/server@2.0.0`・`@minecraft/server-ui@2.0.0` で全スクリプトを検査（存在しないAPI・誤った引数がないこと）
- **静的検証**：JSON構文、manifest の UUID・相互依存、import 先の実在、アイコン・言語キーの対応
- **模擬エンジンでのテスト**：`@minecraft/server` の動作を真似た模擬実装の上で `main.js` を起動し、ワールド再起動を3回またいで動作を確認（単体・統合テスト30件すべて成功）。模擬実装は実機を完全には再現しません

| 判定項目 | 実機 | 模擬エンジン・単体テスト |
|---|---|---|
| ワールドを正常に起動できる | **未検証** | 起動処理が正常終了することを確認。`worldLoad` が届かない場合の予備初期化も確認 |
| 初回参加時にデータが生成される | **未検証** | 人間・Lv1・無職・能力一般人相当・金貨0で生成されることを確認 |
| 再参加時にデータが維持される | **未検証** | 退出→再参加、再起動→再参加の両方で維持を確認。冒険者の書の重複配布がないことも確認 |
| 複数人のデータが混同されない | **未検証** | 4人同時・途中退出・途中参加・同一IDの複製プレイヤーでも混同しないことを確認 |
| ワールド再起動後もデータが維持される | **未検証** | 3回の起動（シャットダウン処理なしの強制終了を含む）で維持を確認 |
| RPG専用メニューが開く | **未検証** | 冒険者の書の使用（空中・ブロック）で11項目のメニューが開き、全ページを開閉できることを確認 |
| 重大な Script API エラーが発生しない | **未検証** | 全シナリオでエラー0件。型チェックで API の存在を確認 |

実機での確認は [動作確認手順](動作確認手順.md) に沿って行ってください。

## 実装済み機能

### アドオンの基本構造
- ビヘイビアーパック・リソースパック・manifest（BP⇔RP 相互依存）
- 安定版 Script API のみ使用（`@minecraft/server 2.0.0`、`@minecraft/server-ui 2.0.0`）。実験的機能は不要
- 機能別のファイル分割（49ファイル）。ゲーム内容は `content/` のレジストリに追加する方式（ID重複を拒否）

### プレイヤーデータ管理（4-2）
次の項目をプレイヤーごとに独立して保存する構造を用意しました（具体的な成長処理は未実装）。
プレイヤー識別ID／レベル／経験値／職業／職業レベル（職業別）／HP・MP・スタミナ（現在値・最大値）／基礎能力値（筋力・体力・敏捷・器用・知力・精神・幸運）／未使用能力ポイント／先天的才能／後天的才能／隠された潜在能力（抽選用シード付き）／スキル／熟練度／装備（9スロット）／金貨／称号／冒険者ランク／クエスト進行／NPC好感度／個人倉庫／ダンジョン攻略実績／限界突破状況／種族／個人設定／参加記録

### ワールド共有データ（4-3）
メインストーリー進行／地域解放状況／ダンジョン攻略状況／ボス討伐状況／世界唯一の装備の所有状況／世界唯一の称号の獲得状況／特殊イベント／ダンジョンの途中再開情報／データ構造のバージョン（＋アドオンのバージョン履歴・復旧記録）／ワールド設定（行動制限・人数別調整・NPC補完の切り替え）

### 初回参加処理（4-4）
- 初回：種族 人間・レベル1・無職・能力 一般人相当（全能力5、HP100/MP10/スタミナ100）・金貨0、その他初期状態
- 冒険者の書を配布（捨てられない・死亡時に失わない）
- 再参加：初期化せず保存データを読み込む（参加処理は何度呼ばれても二重実行しない）

### セーブシステム（4-5）
- **自動保存**：10秒ごとに「変更があったデータ」だけを最大2件ずつ保存（負荷分散）
- **重要な更新時の保存**：参加・退出・設定変更・行動制限変更は即時保存
- **終了時の保存**：ワールド終了直前イベントで全保存（実機で書き込み可能かは未検証。自動保存で補う）
- **再ログイン時の読み込み**・**ワールド再起動後のデータ維持**
- **データ破損の検知**：長さ＋チェックサム＋JSON構文で検証
- **二重保存**：A/B 2つの保存枠を交互に使用。保存の確定は最後の1書き込みで行うため、保存中の中断でも前回データが残る
- **復旧処理**：最新の枠が壊れていれば前回の枠から復旧。管理情報が壊れていても保存枠から新しい方を復旧。両方壊れていれば破損データを退避してから初期化し、本人と管理者に通知
- **データ構造のバージョン管理・移行**：データごとにバージョンを記録し、読み込み時に順番に移行。欠けた項目は自動補完、未知の項目は削除しない
- **新しいバージョンのデータの保護**：アドオンを古い版に戻した場合などは読み取り専用にして上書きしない
- **識別IDの復旧**：プレイヤー側の識別IDが失われても、索引から同じデータに戻す
- 保存は ASCII 化して分割するため、日本語や絵文字があっても保存上限の計算が正確で、分割による文字化けが起きない

### マルチプレイ基盤（4-6）
- プレイヤーごとにデータを完全分離（アドオン独自の識別IDで管理し、名前は識別に使わない）
- 同じ識別IDを持つ別人が同時参加した場合は新しいIDを発行してデータ共有を防ぐ
- ストーリー等はワールドで共有
- 不在プレイヤーのデータは変更されない（オフラインのプレイヤーへの更新は拒否）
- 途中参加・途中退出に対応
- 人数別難易度の倍率表（1～4人）と NPC 補完の差し込み口（適用処理は未実装）
- 5人以上の参加時は警告表示

### RPG専用メニュー（4-7）
- 冒険者の書を「使う」と開く（空中・ブロックどちらに向けても可）。しゃがみ操作は不使用
- ステータス／職業／スキル／才能／装備／称号／クエスト／冒険者情報／ダンジョン情報／倉庫／設定
- 各ページで保存データの現在値を表示し、未実装の機能は「今後実装予定」と表示
- 設定：保存通知の ON/OFF、今すぐ保存、データ状態の確認、［管理者］行動制限の設定、［管理者］最近のエラー
- チャット欄が開いていて表示できない場合は自動で再試行、連打による多重表示を防止

### 完全RPG型の基盤（4-8）
- ブロック破壊（採掘）・ブロック設置（建築）・ブロックの使用（作業台・かまど・チェスト等）を個別に禁止できる仕組み
- 既定ではすべて OFF。管理者が設定画面またはコマンドで切り替え
- クリエイティブモードと管理者タグの所持者は対象外

### 処理負荷対策（4-9）
- 毎tick処理なし（自動保存の確認は10秒に1回のみ）
- データはメモリ上に保持し、保存領域への読み書きは参加・退出・保存時だけ
- 自動保存は1回あたりの件数を制限して分散
- 退出したプレイヤーのデータはメモリから解放
- 全イベント処理をエラー隔離し、1つの失敗がほかに波及しない。エラーは管理者に通知し、設定画面で確認可能

## 既知の問題・制約

1. **実機で未検証**です。上表のとおり、すべての判定項目は模擬環境での確認にとどまります。
2. **冒険者の書の「使用」イベント**：特別な使用動作（食べる・投げる等）を持たない独自アイテムで `itemUse` が発火することを前提にしています。実機で開かない場合の代替として、ブロックに向けての使用（別イベントで処理）と `/scriptevent noguchi:menu` を用意しています。
3. **終了時の保存**：ワールド終了直前イベント内で保存領域に書き込めるかは未確認です。書き込めない場合でも、重要な更新は即時保存、それ以外は最大約10秒分の変更が失われる可能性があるにとどまります。
4. **設置の禁止は簡易判定**です。手に持ったアイテムと同じIDのブロックが存在する場合のみ禁止します。レッドストーンの粉・種・バケツなど「アイテムIDと設置されるブロックIDが異なるもの」は止められません。
5. **クラフトの禁止**：安定版 API にクラフト自体を止める仕組みがないため、作業台などのブロック使用を禁止する方式です。インベントリ内の2×2クラフトは止められません。
6. **5人以上の参加**は拒否せず警告のみです（プレイヤーの強制退出は行わない方針）。
7. **HP・MP・スタミナ**は RPG 内部の値で、バニラのハート（体力）とはまだ連動していません。
8. **日時表示**は UTC です（実行環境のタイムゾーンを取得できないため）。
9. **識別IDの復旧**は、Minecraft がプレイヤーに割り当てるエンティティIDがワールド内で変わらないことを前提にしています。通常はプレイヤー本人に保存した識別IDが使われるため、この経路はほとんど使われません。
10. **管理者タグの付与**にはチートの有効化が必要です（チートを有効にすると実績が解除されなくなります）。
11. **ビヘイビアーパックの UUID を変えるとセーブデータが読めなくなります**（動的プロパティはパックごとに保存されるため）。今後のアップデートでも絶対に変更しないでください。
12. 対応バージョンは **1.21.90 以降**です。それより古い Switch 本体のバージョンでは読み込まれません。
