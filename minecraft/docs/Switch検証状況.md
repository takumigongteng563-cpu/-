# Switch での検証状況・操作方式の実現性

## 対象バージョン

| 項目 | 値 |
|---|---|
| Minecraft 統合版 | **1.21.90 以降**（manifest の `min_engine_version`） |
| Script API | `@minecraft/server` **2.0.0**（安定版）、`@minecraft/server-ui` **2.0.0**（安定版） |
| 実験的機能（ベータAPI） | 使用しない |
| アドオンのバージョン | 0.2.1（パックのUUIDは第1弾から変更なし） |

## 検証状況

**Nintendo Switch・PC・Realms のいずれの実機でも、まだ一度も動作確認していません。** 開発環境に Minecraft を動かす手段がないためです。

行った確認は次のとおりです。

- 公式の型定義（2.0.0）による型チェック：使っている API がすべて安定版に存在することを確認
- 模擬エンジン上でのテスト（81件成功）：イベントの発生を模擬して処理の流れを確認
- 第1弾・第2弾のコードで作った実際のセーブデータからの移行テスト

実機で確認すべき項目は [動作確認手順](動作確認手順.md) の 19～22 にまとめています。

## 操作方式（ホットバー複数操作）の実現性

最終仕様 第11章の「すべての操作判定が安定版 Script API で実現可能か確認し、困難なものは代替案を報告すること」への回答です。
評価は API の仕様（型定義）に基づくもので、**Switch 実機での確認は済んでいません**。

| 操作 | 判定に使う安定版 API | 実現性 | 懸念点 | 代替案 |
|---|---|---|---|---|
| 通常使用 | `world.afterEvents.itemUse` | ○ 可能（見込み） | 独自アイテムで発火するかは実機未確認（冒険者の書と同じ条件） | ブロックに向けた使用（`playerInteractWithBlock`）でも判定する |
| ジャンプ中に使用 | `Player.isJumping` / `Player.isOnGround` | ○ 可能（見込み） | ジャンプ直後の数tickは地上判定になる可能性 | 「空中（isOnGround=false）」も含めて判定済み |
| ダッシュ中に使用 | `Player.isSprinting` | △ 要確認 | **アイテムを使う操作（ZL）でダッシュが解除される場合**、使用時点で isSprinting=false になる | 使用直前（数tick前）のダッシュ状態を記録して判定する方式に変更できる（`balance/input.js` に猶予時間を追加する想定） |
| しゃがみながら溜めて使用 | `Player.isSneaking` を2tickごとに確認し、しゃがみ続けた時間を溜めとする | ○ 可能（見込み） | Switch のしゃがみが「切り替え式」設定の場合も同様に判定できる見込み | ― |
| 長時間溜めて使用 | ①`itemStartUse`/`itemReleaseUse`（押して離した時間）②しゃがみ時間 | △ 要確認 | ①は**使用時間を持つアイテム**でのみ発火する。独自アイテムに `minecraft:use_modifiers` だけを付けて押し続けの判定になるかは未確認 | ②しゃがみ続けた時間（2秒以上）でも奥義と判定するため、①が使えなくても長時間溜めは成立する。①は第4弾で武器・魔導書の設計時に、弓のような使用時間を持つ構成も含めて検証する |

### 優先順位・誤発動防止・キャンセル・クールタイム（設計済み・実装済み）

- 優先順位：奥義 ＞ 大技 ＞ 移動技 ＞ 中技 ＞ 小技
- 誤発動防止：しゃがまずに中途半端な長さ（0.4秒～2秒）で押して離した場合は不発
- キャンセル：押している間に持ち替えた場合は不発。しゃがみを解くと溜めはリセット
- 二重判定防止：使用開始の `itemUse` と離した時の判定が重ならないようにしている
- クールタイム：技ごとのクールタイムと、全技共通の再使用待ち（0.3秒）
- 未習得の技・MPやスタミナ不足の技は発動しない（消費もしない）

### 実機での確認方法

1. 管理者タグを付ける（`/tag @s add noguchi_admin`）
2. 冒険者の書 → 設定 → テスト機能 →「操作判定テスト ON/OFF」（または `/scriptevent noguchi:input_test on` と `/scriptevent noguchi:give_focus`）
3. 「修練の触媒」を手に持ち、5種類の操作で使う
4. 画面下に「操作判定: ○○」と表示されるので、意図した操作と一致するか記録する

## そのほかの最終仕様の項目で、実機確認や設計上の注意が必要なもの（第4弾以降）

現時点で判明している技術的な注意点です。実装時に改めて検証し、困難な場合は代替案を報告します。

| 仕様 | 使う予定の機能 | 注意点 |
|---|---|---|
| 固定マップ（100ステージ） | 構造物ファイル（.mcstructure）＋ `world.structureManager.place`（安定版にあり） | 1回で設置できる大きさに上限があり、大きなマップは分割して少しずつ設置する必要がある。プレイヤーがいない場所（未読込のチャンク）には設置できないため、テレポート先の読み込みを待つ処理が必要 |
| 王国の約100棟の建物 | 同上（`kingdomService.processBuildQueue` で1件ずつ配置する基盤を用意済み） | 同上 |
| ボスバー | ボス用の独自エンティティ（ビヘイビアーパックのエンティティ定義） | Script API だけではボスバーを出せないため、エンティティ側の定義が必要 |
| 専用BGM | リソースパックの音声＋ `playSound` / `/music` コマンド | 音源ファイルが大きいとパックの容量と Switch の読み込み時間に影響 |
| カメラ演出・暗転 | `Player.camera`（安定版） | Switch での表示確認が必要 |
| 魔神野口の透明化 | 透明化の効果やエンティティの見た目の切り替え | 「攻略可能な対抗手段」とセットで設計する |
| 仲間NPC・召喚獣 | 独自エンティティ | 同時稼働数の上限を設けて Switch の負荷を抑える |
| 仲間のHP表示・敵のHP表示 | アクションバー／スコアボード／ボスバー | アクションバーは1つしかないため、表示の優先順位の設計が必要 |
